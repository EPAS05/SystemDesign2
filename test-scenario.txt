====================================================================
ТЕСТОВЫЙ СЦЕНАРИЙ
====================================================================
Шлюз:              http://localhost:8080
Catalog service:   catalog-service:8081        (gRPC внутри compose)
Configuration svc: configuration-service:8082  (gRPC внутри compose)

Единая сущность — ИЗДЕЛИЕ (product). Составной объект — это изделие,
в BOM которого входят другие изделия.

============================================================================
ПОДГОТОВКА (подставить свои UUID; в set НЕТ пробелов вокруг "=")
============================================================================
set BASE=http://localhost:8080


============================================================================
ЧАСТЬ A. CATALOG SERVICE
============================================================================
ДВА ДЕРЕВА УЗЛОВ (nodes) — просто для группировки изделий:
  1) Root -> Line            (сюда крепятся "детали": Resistor, Capacitor)
  2) Products -> Assemblies  (сюда крепится сборка Board 123)
Деревья независимы; связи между изделиями задаются только через BOM.

----------------------------------------------------------------------------
A1. PING (проверка шлюза и обоих сервисов)
    GET /v1/ping
----------------------------------------------------------------------------
curl -s "%BASE%/v1/ping"

Ожидаем: 200, {"message":{...catalog...,...configuration...}}.

----------------------------------------------------------------------------
A2. СОЗДАТЬ КОРНЕВОЙ УЗЕЛ (без parent_id)
    POST /v1/nodes   { name }   body: "*"
----------------------------------------------------------------------------
curl -s -X POST "%BASE%/v1/nodes" -H "Content-Type: application/json" -d "{\"name\":\"Root\"}"

Ожидаем: 200, Node { "id", "name":"Root", "parentId":"" }.

Скопировать id:
set NODE_ROOT=

----------------------------------------------------------------------------
A3. СОЗДАТЬ ДОЧЕРНИЙ УЗЕЛ
    POST /v1/nodes   { parentId, name }
----------------------------------------------------------------------------
curl -s -X POST "%BASE%/v1/nodes" -H "Content-Type: application/json" -d "{\"parentId\":\"%NODE_ROOT%\",\"name\":\"Line\"}"

Ожидаем: 200, Node со связкой parentId=%NODE_ROOT%.
set NODE_CHILD=<id из ответа>

----------------------------------------------------------------------------
A4. СПИСОК ДЕТЕЙ УЗЛА
    GET /v1/nodes/{parent_id}/children
----------------------------------------------------------------------------
curl -s "%BASE%/v1/nodes/%NODE_ROOT%/children"

Ожидаем: 200, { "nodes": [ ...один узел Line... ] }
(если деталей нет — nodes=[]).

----------------------------------------------------------------------------
A5. ПОЛУЧИТЬ УЗЕЛ ПО id
    GET /v1/nodes/{id}

Ожидаем: 200, Node { "id", "parentId", "name" }.

----------------------------------------------------------------------------
A6. ПЕРЕИМЕНОВАТЬ УЗЕЛ
    PATCH /v1/nodes/{id}   { name }
----------------------------------------------------------------------------

Ожидаем: 200, Node с новым name. parent_id не меняется (в теле только name).

----------------------------------------------------------------------------
A7. СОЗДАТЬ ИЗДЕЛИЯ В УЗЛЕ LINE
    POST /v1/products   { nodeId, name }
----------------------------------------------------------------------------
curl -s -X POST "%BASE%/v1/products" -H "Content-Type: application/json" -d "{\"nodeId\":\"%NODE_CHILD%\",\"name\":\"Resistor\"}"

curl -s -X POST "%BASE%/v1/products" -H "Content-Type: application/json" -d "{\"nodeId\":\"%NODE_CHILD%\",\"name\":\"Capacitor\"}"

Ожидаем: 200, Product { "id", "nodeId", "name" }.

-- Переименовать Capacitor -> Condenser (UpdateProduct):
curl -s -X PATCH "%BASE%/v1/products/%PROD_B%" -H "Content-Type: application/json" -d "{\"name\":\"Condenser\"}"

Ожидаем: 200, Product с новым name.

----------------------------------------------------------------------------

============================================================================
ЧАСТЬ B. CONFIGURATION SERVICE
============================================================================
Изделия перешли из A:
  PRODUCT (сборка) -> %PRODUCT%
  PROD_A -> %PROD_A%, PROD_B -> %PROD_B%
(это id из БД каталога; в configuration они хранятся как uuid без FK).

----------------------------------------------------------------------------
B1. СОЗДАТЬ ДЕФОЛТНЫЙ BOM СБОРКИ
    POST /v1/products/{product_id}/boms   { isDefault: true }
----------------------------------------------------------------------------
curl -s -X POST "%BASE%/v1/products/%PRODUCT%/boms" -H "Content-Type: application/json" -d "{\"isDefault\":true}"

Ожидаем: 200, Bom { "id", "productId":"%PRODUCT%", "isDefault":true, "rows":[] }.
set BOM_DEFAULT=<id из ответа>

Автосоздания дефолта при отсутствии НЕТ — только явный запрос выше
(автосоздание позже добавим в шлюзе). Повтор вызова идемпотентен.

----------------------------------------------------------------------------
B2. ДОБАВИТЬ СТРОКИ (изделия, входящие в сборку) В ДЕФОЛТНЫЙ BOM
    POST /v1/boms/{bom_id}/rows   { productId, quantity }
----------------------------------------------------------------------------
curl -s -X POST "%BASE%/v1/boms/%BOM_DEFAULT%/rows" -H "Content-Type: application/json" -d "{\"productId\":\"%PROD_A%\",\"quantity\":\"5\"}"

curl -s -X POST "%BASE%/v1/boms/%BOM_DEFAULT%/rows" -H "Content-Type: application/json" -d "{\"productId\":\"%PROD_B%\",\"quantity\":\"2.5\"}"

Ожидаем: 200, BomRow { "id", "productId", "quantity" }.
set ROW1=<id первой строки>   (PROD_A=5)

----------------------------------------------------------------------------
B3. ПОЛУЧИТЬ BOM ПО id
    GET /v1/boms/{id}
----------------------------------------------------------------------------
curl -s "%BASE%/v1/boms/%BOM_DEFAULT%"

Ожидаем: 200, Bom c 2 строками (PROD_A=5, PROD_B=2.5).

----------------------------------------------------------------------------
B4. СПИСОК BOM СБОРКИ (default + модификации)
    GET /v1/products/{product_id}/boms
----------------------------------------------------------------------------
curl -s "%BASE%/v1/products/%PRODUCT%/boms"

Ожидаем: 200, { "boms":[ ... ] }, первым is_default=true.
BOM сборки = элемент с isDefault:true.

----------------------------------------------------------------------------
B5. ОБНОВИТЬ СТРОКУ
    PATCH /v1/boms/rows/{id}   { productId, quantity }
----------------------------------------------------------------------------
curl -s -X PATCH "%BASE%/v1/boms/rows/%ROW1%" -H "Content-Type: application/json" -d "{\"productId\":\"%PROD_B%\",\"quantity\":\"7\"}"

Ожидаем: 200, BomRow с новыми productId/quantity.

----------------------------------------------------------------------------
B6. ЗАМЕНИТЬ ВСЕ СТРОКИ BOM
    PUT /v1/boms/{bom_id}/rows   { rows:[{productId, quantity}] }
----------------------------------------------------------------------------
curl -s -X PUT "%BASE%/v1/boms/%BOM_DEFAULT%/rows" -H "Content-Type: application/json" -d "{\"rows\":[{\"productId\":\"%PROD_A%\",\"quantity\":\"10\"}]}"

Ожидаем: 200, Bom с единственной строкой PROD_A=10.
ВНИМАНИЕ: старые строки (в т.ч. ROW1) удалены, id строк новые.

----------------------------------------------------------------------------
B7. СОЗДАТЬ МОДИФИКАЦИЮ (копирует строки дефолта)
    POST /v1/products/{product_id}/boms   { isDefault:false, name }
----------------------------------------------------------------------------
curl -s -X POST "%BASE%/v1/products/%PRODUCT%/boms" -H "Content-Type: application/json" -d "{\"isDefault\":false,\"name\":\"Mod X\"}"

Ожидаем: 200, Bom isDefault:false, name:"Mod X",
rows = копия строк дефолта (PROD_A=10).
set BOM_MOD=<id из ответа>

----------------------------------------------------------------------------
B8. ПРОСМОТРЕТЬ СОЗДАННУЮ МОДИФИКАЦИЮ ПО id
    GET /v1/boms/{id}
----------------------------------------------------------------------------
curl -s "%BASE%/v1/boms/%BOM_MOD%"

Ожидаем: 200, Bom:
  "id":        %BOM_MOD%
  "productId": %PRODUCT%
  "isDefault": false
  "name":      "Mod X"
  "rows":      [ PROD_A=10 ]   (копия дефолта на момент создания)

----------------------------------------------------------------------------
B9. ПРОСМОТРЕТЬ ВСЕ BOM СБОРКИ (default + модификация)
    GET /v1/products/{product_id}/boms
----------------------------------------------------------------------------
curl -s "%BASE%/v1/products/%PRODUCT%/boms"

Ожидаем: 200, { "boms": [ ... ] }, 2 элемента — порядок:
  1) default:  "isDefault": true,  name:"",      rows=[PROD_A=10]
  2) модификация: "isDefault": false, name:"Mod X", rows=[PROD_A=10]
BOM сборки по умолчанию = элемент с isDefault:true.

----------------------------------------------------------------------------
B10. ДОБАВИТЬ СТРОКУ В МОДИФИКАЦИЮ
----------------------------------------------------------------------------
curl -s -X POST "%BASE%/v1/boms/%BOM_MOD%/rows" -H "Content-Type: application/json" -d "{\"productId\":\"%PROD_B%\",\"quantity\":\"1\"}"

Ожидаем: 200, строка только в модификации.
set ROW_MOD=<id из ответа>

Проверить: повторно GET модификации по id — теперь 2 строки
(копия дефолта PROD_A=10 + добавленная PROD_B=1). Дефолтный BOM не тронут:
curl -s "%BASE%/v1/boms/%BOM_MOD%"
curl -s "%BASE%/v1/boms/%BOM_DEFAULT%"


========----------------------------------------------------------------------------
B11. СПИСОК РЕВИЗИЙ ДЕФОЛТНОГО BOM (история изменений)
     GET /v1/boms/{bom_id}/revisions
----------------------------------------------------------------------------
curl -s "%BASE%/v1/boms/%BOM_DEFAULT%/revisions"

Ожидаем: 200, {"revisions":[ ... ]} — 5 версий в порядке возрастания:
  rev 1 — создание BOM       (строк нет)
  rev 2 — B2 добавлен PROD_A=5
  rev 3 — B2 добавлен PROD_B=2.5
  rev 4 — B5 строка ROW1 обновлена (PROD_B=7)

B12. СНИМОК ПЕРВОЙ РЕВИЗИИ (состояние на момент создания)
     GET /v1/boms/{bom_id}/revisions/{revision}
----------------------------------------------------------------------------
curl -s "%BASE%/v1/boms/%BOM_DEFAULT%/revisions/1"

Ожидаем: 200, {"revision":1, "changedAt":..., "rows":[]} — BOM создан пустым.

----------------------------------------------------------------------------
B13. СНИМОК ПРОМЕЖУТОЧНОЙ РЕВИЗИИ (после добавления строк)
----------------------------------------------------------------------------
curl -s "%BASE%/v1/boms/%BOM_DEFAULT%/revisions/3"

Ожидаем: 200, rows: [ PROD_A=5, PROD_B=2.5 ] — т.е. ДО обновления строк.

----------------------------------------------------------------------------
B14. СНИМОК ПОСЛЕДНЕЙ РЕВИЗИИ = текущее состояние

Ожидаем: обе команды дают один состав: rows: [ PROD_A=10 ].
(GetBom = живое/текущее состояние; revisions = неизменяемые снимки.)

----------------------------------------------------------------------------
B15. РЕВИЗИИ МОДИФИКАЦИИ (создание-копия -> добавление строки)
----------------------------------------------------------------------------

Ожидаем: 2 версии:
  rev 1 — создание модификации (копия базовой: PROD_A=10)
  rev 2 — B10 добавлен PROD_B=1
Дефолтный BOM в эти версии не замешан.

----------------------------------------------------------------------------
B16. РЕВИЗИЯ НЕСУЩЕСТВУЮЩЕЙ ВЕРСИИ -> 404

Ожидаем: 404.

ЧАСТЬ C. ЦИКЛЫ, УДАЛЕНИЯ, НЕГАТИВНЫЕ ПРОВЕРКИ

----------------------------------------------------------------------------
C1. ИЗДЕЛИЕ НЕ МОЖЕТ СОДЕРЖАТЬ САМО СЕБЯ -> 400
    POST /v1/boms/{bom_id}/rows   { productId == productId BOM }
----------------------------------------------------------------------------
-- В BOM сборки PRODUCT пытаемся добавить саму сборку PRODUCT:
curl -s -i -X POST "%BASE%/v1/boms/%BOM_DEFAULT%/rows" -H "Content-Type: application/json" -d "{\"productId\":\"%PRODUCT%\",\"quantity\":\"1\"}"

Ожидаем: 400, "product cannot contain itself".

-- То же для UpdateBomRow: попытка поставить строке productId самой сборки
-- (ROW_MOD жив: B6 заменил строки дефолта, поэтому ROW1 уже не существует):
curl -s -i -X PATCH "%BASE%/v1/boms/rows/%ROW_MOD%" -H "Content-Type: application/json" -d "{\"productId\":\"%PRODUCT%\",\"quantity\":\"1\"}"

Ожидаем: 400, "product cannot contain itself".

----------------------------------------------------------------------------
C2. ЦИКЛ ЧЕРЕЗ ЦЕПОЧКУ -> 400
----------------------------------------------------------------------------
-- Сборка PRODUCT уже содержит PROD_A (BOM_DEFAULT: PROD_A=10).
-- Создаём BOM для PROD_A и пытаемся вложить в него сборку PRODUCT:
-- это замкнуло бы цикл PRODUCT -> PROD_A -> PRODUCT.
curl -s -X POST "%BASE%/v1/products/%PROD_A%/boms" -H "Content-Type: application/json" -d "{\"isDefault\":true}"

Ожидаем: 200, Bom PROD_A.
set BOM_A=<id из ответа>

curl -s -i -X POST "%BASE%/v1/boms/%BOM_A%/rows" -H "Content-Type: application/json" -d "{\"productId\":\"%PRODUCT%\",\"quantity\":\"1\"}"

Ожидаем: 400, "bom would create a cycle".

-- Аналогично ReplaceBomRows:
curl -s -i -X PUT "%BASE%/v1/boms/%BOM_A%/rows" -H "Content-Type: application/json" -d "{\"rows\":[{\"productId\":\"%PRODUCT%\",\"quantity\":\"1\"}]}"

Ожидаем: 400, "bom would create a cycle".

-- Корректное вложение БЕЗ цикла проходит: PROD_A <- PROD_B (никаких обратных путей нет):
curl -s -X POST "%BASE%/v1/boms/%BOM_A%/rows" -H "Content-Type: application/json" -d "{\"productId\":\"%PROD_B%\",\"quantity\":\"3\"}"

Ожидаем: 200, BomRow PROD_B=3.

-- Убрать тестовый BOM PROD_A, чтобы не мешать дальнейшим шагам:
curl -s -X DELETE "%BASE%/v1/boms/%BOM_A%"

Ожидаем: 200, {}.

----------------------------------------------------------------------------
C9. НЕГАТИВНЫЕ ПРОВЕРКИ
----------------------------------------------------------------------------
-- ping без проблем, но каждый битый запрос должен вернуть ошибку:

-- create node без name -> 400
curl -s -i -X POST "%BASE%/v1/nodes" -H "Content-Type: application/json" -d "{\"name\":\"\"}"

-- create product без nodeId -> 400
curl -s -i -X POST "%BASE%/v1/products" -H "Content-Type: application/json" -d "{\"nodeId\":\"\",\"name\":\"X\"}"

-- create product с несуществующим node -> 404 (node not found)
curl -s -i -X POST "%BASE%/v1/products" -H "Content-Type: application/json" -d "{\"nodeId\":\"00000000-0000-0000-0000-000000000000\",\"name\":\"X\"}"

-- get несуществующего узла -> 404
curl -s -i "%BASE%/v1/nodes/00000000-0000-0000-0000-000000000000"

-- get несуществующего BOM -> 404
curl -s -i "%BASE%/v1/boms/00000000-0000-0000-0000-000000000000"

-- list children без parent -> 400
curl -s -i "%BASE%/v1/nodes//children"

-- добавление строки с quantity <= 0 -> 400
curl -s -i -X POST "%BASE%/v1/boms/%BOM_DEFAULT%/rows" -H "Content-Type: application/json" -d "{\"productId\":\"%PROD_A%\",\"quantity\":\"0\"}"

-- добавление строки без productId -> 400
curl -s -i -X POST "%BASE%/v1/boms/%BOM_DEFAULT%/rows" -H "Content-Type: application/json" -d "{\"productId\":\"\",\"quantity\":\"1\"}"

-- модификация без name -> 400
curl -s -i -X POST "%BASE%/v1/products/%PRODUCT%/boms" -H "Content-Type: application/json" -d "{\"isDefault\":false}"

-- BOM default для несуществующего изделия всё равно создаётся (нет FK) ->
   200; изделие с этим id в каталоге отсутствует. Это ожидаемое поведение:
curl -s -i -X POST "%BASE%/v1/products/00000000-0000-0000-0000-000000000000/boms" -H "Content-Type: application/json" -d "{\"isDefault\":true}"


============================================================================
ЧАСТЬ D. МАРШРУТНАЯ ТЕХНОЛОГИЯ
============================================================================
Выполнять после части B и до части C: используются живые PRODUCT, PROD_A,
PROD_B, BOM_DEFAULT. Все количества — в штуках, без единиц измерения.

----------------------------------------------------------------------------
D1. СПРАВОЧНИКИ
    POST /v1/operation-classes, /v1/equipment, /v1/tools
----------------------------------------------------------------------------
curl -s -X POST "%BASE%/v1/operation-classes" -H "Content-Type: application/json" -d "{\"code\":\"CUT\",\"name\":\"Резка\",\"hourlyRate\":\"500\"}"
curl -s -X POST "%BASE%/v1/operation-classes" -H "Content-Type: application/json" -d "{\"code\":\"WELD\",\"name\":\"Сварка\",\"hourlyRate\":\"800\"}"
curl -s -X POST "%BASE%/v1/operation-classes" -H "Content-Type: application/json" -d "{\"code\":\"ASSY\",\"name\":\"Сборка\",\"hourlyRate\":\"600\"}"

set OP_CUT=<id CUT>
set OP_WELD=<id WELD>

D4. ВЛОЖЕННЫЙ МАРШРУТ КОМПОНЕНТА
    POST /v1/products/{product_id}/boms
    POST /v1/boms/{bom_id}/route/rows

D5. МОДИФИКАЦИЯ: НАСЛЕДОВАНИЕ, ПЕРЕКРЫТИЕ, ИСКЛЮЧЕНИЕ
----------------------------------------------------------------------------
curl -s -X POST "%BASE%/v1/products/%PRODUCT%/boms" -H "Content-Type: application/json" -d "{\"isDefault\":false,\"name\":\"Mod Route\"}"
set BOM_MOD_ROUTE=<id из ответа>

curl -s "%BASE%/v1/boms/%BOM_MOD_ROUTE%/route/rows"
Ожидаем: 2 унаследованные строки (inherited=true).

-- Своя строка seq=15:
curl -s -X POST "%BASE%/v1/boms/%BOM_MOD_ROUTE%/route/rows" -H "Content-Type: application/json" -d "{\"seq\":15,\"operationClassId\":\"%OP_ASSY%\",\"productId\":\"%PROD_A%\",\"quantity\":\"1\",\"laborNorm\":\"0.3\"}"

-- Перекрыть унаследованную строку seq=10:
curl -s -X PATCH "%BASE%/v1/boms/%BOM_MOD_ROUTE%/route/rows/%ROUTE1%" -H "Content-Type: application/json" -d "{\"seq\":10,\"operationClassId\":\"%OP_CUT%\",\"productId\":\"%PROD_A%\",\"quantity\":\"10\",\"laborNorm\":\"0.4\"}"

-- Исключить унаследованную строку seq=20:
curl -s -X PATCH "%BASE%/v1/boms/%BOM_MOD_ROUTE%/route/rows/%ROUTE2%" -H "Content-Type: application/json" -d "{\"seq\":20,\"operationClassId\":\"%OP_WELD%\",\"productId\":\"%PROD_B%\",\"quantity\":\"0\",\"laborNorm\":\"0\",\"isExcluded\":true}"

Ожидаем: в GET маршрута модификации 2 строки (seq=10 inherited=false,
seq=15 inherited=false); seq=20 отсутствует. Дефолтный BOM не изменён.

D6. РУЧНАЯ ЦЕНА BOM БЕЗ МАРШРУТА
    PATCH /v1/boms/{id}/price   { price, priceManual }

curl -s -i -X PATCH "%BASE%/v1/boms/%BOM_DEFAULT%/price" -H "Content-Type: application/json" -d "{\"price\":\"1\",\"priceManual\":true}"
Ожидаем: 412.
